# 社区舞蹈队 · 排练报名与演出走位协作台

React 18 + TypeScript + Zustand + Vite 实现的单页应用。围绕**同一场演出记录**，让队长、队员、服装负责人、文化站、音响师、志愿者六类角色协同完成：报名 → 排练签到 → 走位编排 → 服装 → 节目审查 → 演出当天 → 归档 的完整流程。

## 本地启动

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，默认 http://localhost:5173
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm run preview    # 预览生产构建，默认 http://localhost:4173
npm test           # 运行 store 层冒烟测试（42 项断言）
```

### Docker 一键启动

```bash
docker compose up -d --build     # 构建并后台启动
# 打开 http://localhost:8080
docker compose logs -f web       # 查看日志
docker compose down              # 停止
```

多阶段构建（`node:20-alpine` 编译 → `nginx:1.27-alpine` 托管 `dist/`，含 SPA 回退与静态资源缓存）；也可 `docker build -t community-dance-stage . && docker run -p 8080:80 community-dance-stage`。

## 功能与异常场景对照

- **报名**：队长发布广场舞/民族舞/合唱伴舞/节庆演出（可标记文艺汇演海选）；记录队员年龄、身高、联系方式、服装尺码、可排练时间、是否参加正式演出、身体注意事项、动作熟练度。
- **排练签到**：平板大按钮出勤/请假/缺席；上传曲目版本（自动通知音响师）；动作分段与重点练习成员标记；老年队员健康提醒条。
- **走位编排**：队形网格（前排高亮）；最近排练请假/缺席的队员站位标红闪烁，队长可快速发现前排缺席影响；队员点击放置/撤下；**场地缩小**一键压缩列数，被裁队员进入「待安置」并生成调整记录与通知；队形变化说明。
- **临时替位走位（演出前一天突发）**：
  - 队长在走位页选择请假/缺席的在队队员，系统按**身高接近（25%）＋ 动作熟练度（40%）＋ 排练出勤率（35%）**对未占位候补队员打分排序并推荐，逐项展示身高差、星级熟练度、出勤率、是否参加最后一次排练；
  - 队长两步确认（选择 → 最终确认下发）后：替位队员自动站上请假者原站位，走位图上以紫色「替」角标生成**新走位图**；自动**标记受影响的队形变化**（受替位影响·需重练）；生成**重点排练名单**（替位队员＋同排/后排相邻配合队员）；为替位队员自动建立**免押金临时候补服装**记录；
  - 确认同时向**替位队员、服装负责人、音响师、队长**下发「演出清单更新」通知，各方在总览/演出当天看到的都是同一份最新清单（演出当天页有「替位后最新演出清单」，含到场状态）；
  - **替位队员未参加最后一次排练时**：走位页、总览（队长）持续红色闪烁风险提示；演出当天页「演出前检查」清单（到场、过走位、候补服装、音响清单四项）未全部核对且替位队员未到场前**继续提示**，全部完成后转绿；
  - 队长可撤销替位，站位、队形变化标记自动恢复，并再次通知各方；全部操作写入走位调整记录。
- **服装**：押金收取、本人/家属代领登记、归还退押金、尺码不合适上报与换货、临时候补服装（免押金、演出后回收）。
- **文化站**：节目主题/人数/时长/音响需求/场地审批；节目审查（「要求调整节目内容」会退回排练阶段）；报名→排练→走位→服装→审核→现场签到连续性链条；多支队伍排练室排期。
- **演出当天**：候场顺序（可提前/延后）、现场签到、替位后最新演出清单、替位演出前检查、现场临时通知、志愿者引导要点、音响需求确认。
- **演出档案**：签到汇总、服装归还、走位调整记录（含替位留痕）、现场照片、下次活动通知。
- **其他**：排练室多队共用（同时段同室冲突自动拦截）、老年队员健康提醒专页（按注意事项生成提醒建议）。

## 验证方式与结论

实际执行过的验证（2026-09-30）：

1. `npm run build`：TypeScript 严格模式类型检查 + Vite 生产构建通过（58 个模块，无错误）。
2. `npm test`：store 层冒烟测试 **42/42 通过**。其中临时替位相关 20 项断言覆盖：候选池仅含未占位候补、综合评分排序（熟练度/出勤/身高权重）、最后一次排练出勤识别、确认后站位替换与替位记录、未参加最后排练风险集合、队形变化自动标记、重点排练名单（替位＋相邻队员）、临时候补服装（免押金待领取）、向服装/音响/队员下发清单更新、风险通知、走位调整日志、撤销后站位与变化标记恢复。其余 22 项覆盖原有流程（报名生成押金、请假识别、唯一站位、场地缩小裁列、曲目通知、审查流转、服装全流程、排练室冲突、现场签到、候场顺序、连续性判定）。
3. `npm run dev` 启动后 `curl http://localhost:5173/` 返回 200；`npm run preview` 生产预览 `curl /` 与构建产物 JS 资源均返回 200。
4. Docker 配置（Dockerfile / docker-compose.yml / nginx.conf）已按项目实际构建命令编写；当前执行环境未安装 Docker，镜像构建未在本机实际执行，建议在装有 Docker 的环境用上方命令一键验证。

页面交互（安排替位、切换角色查看更新清单、演出前检查勾选等）可在浏览器中按上表角色逐一操作验证。推荐演练路径：队长角色 →「走位编排」→ 在《丰收锣鼓》替位面板选择张桂芳 → 比较郭晓梅（熟练度高但未参加最后排练，有风险）与何春梅（全勤）→ 确认 → 切换服装/音响/队员角色查看清单 →「演出当天」完成演出前检查。
