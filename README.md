# 社区舞蹈队 · 排练报名与演出走位协作台

React 18 + TypeScript + Zustand + Vite 实现的单页应用。围绕**同一场演出记录**，让队长、队员、服装负责人、文化站、音响师、志愿者六类角色协同完成：报名 → 排练签到 → 走位编排 → 服装 → 节目审查 → 演出当天 → 归档 的完整流程。

## 本地启动

### 方式一：Node 直接运行

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，默认 http://localhost:5173
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm run preview    # 预览生产构建，默认 http://localhost:4173
npm test           # 运行 store 层冒烟测试（46 项断言）
```

### 方式二：Docker 一键启动

```bash
docker compose up --build -d   # 构建并后台运行
# 打开 http://localhost:8080
docker compose down            # 停止
```

镜像采用多阶段构建：Node 20 构建静态资源，nginx 1.27 托管（含 SPA 路由回退）。

## 功能与异常场景对照

- **报名**：队长发布广场舞/民族舞/合唱伴舞/节庆演出（可标记文艺汇演海选）；记录队员年龄、联系方式、服装尺码、可排练时间、是否参加正式演出、身体注意事项。
- **排练签到**：平板大按钮出勤/请假/缺席；上传曲目版本（自动通知音响师）；动作分段与重点练习成员标记；老年队员健康提醒条。
- **走位编排**：队形网格（前排高亮）；最近排练请假/缺席的队员站位标红闪烁，队长可快速发现前排缺席影响；队员点击放置/撤下；**场地缩小**一键压缩列数，被裁队员进入「待安置」并生成调整记录与通知；队形变化说明。
- **临时替位（演出前一天）**：前排队员演出前一天请假时，队长在走位页登记后，系统按**身高接近度、动作熟练度(1-5)、历史排练出勤率**综合打分推荐候补队员（同时标注是否参加最后一次排练）；队长确认后：① 替位队员自动顶替原站位，生成**新走位图**（紫色「替位」标注）；② **自动标记受影响的队形变化**（红色「需重走」徽标）；③ 生成**重点排练名单**（替位本人+同排相邻配合队员+原队员负责的重点分段）；④ 替位队员、服装负责人、音响师分别收到**更新后的演出清单**通知；⑤ 走位调整记录留痕。**若替位队员未参加最后一次排练，队长端总览/走位页及「演出当天→演出前检查」持续红色闪烁提示风险（不可解除，直至演出归档）**；服装页对替位队员标记「替位·加急」；候场与现场签到自动剔除已请假者、标注替位。
- **服装**：押金收取、本人/家属代领登记、归还退押金、尺码不合适上报与换货。
- **文化站**：节目主题/人数/时长/音响需求/场地审批；节目审查（「要求调整节目内容」会退回排练阶段）；报名→排练→走位→服装→审核→现场签到连续性链条；多支队伍排练室排期。
- **演出当天**：候场顺序（可提前/延后）、现场签到、现场临时通知、志愿者引导要点、音响需求确认。
- **演出档案**：签到汇总、服装归还、走位调整记录、现场照片、下次活动通知。
- **其他**：排练室多队共用（同时段同室冲突自动拦截）、老年队员健康提醒专页（按注意事项生成提醒建议）。

## 验证方式与结论

实际执行过的验证（2026-09-30）：

1. `npm run build`：TypeScript 严格模式类型检查 + Vite 生产构建通过（58 个模块，无类型错误）。
2. `npm test`：store 层冒烟测试 **46/46 通过**，覆盖：报名生成服装押金记录、请假/缺席识别、走位唯一站位、场地缩小裁列（待安置+日志+通知）、曲目版本更新通知音响师、审查退回/通过流转、押金/家属代领/尺码换货/归还、排练室冲突拦截、现场签到、候场顺序调整、流程连续性判定；以及本次新增的**临时替位全流程**（24 项）：身高差计算、熟练度/出勤率/最后一次排练综合排序与首选推荐、排除不参加正式演出者、确认后替换站位生成新走位图、受影响队形变化自动标记、重点排练名单生成、走位日志、替位队员/服装/音响三方通知、未参加最后排练的风险快照与持续提示（不可解除）。
3. `npm run dev` 启动后 `curl http://localhost:5173/` 与 `/src/main.tsx` 均返回 200；`npm run preview` 生产预览 `curl http://localhost:4173/` 返回 200。
4. Docker：已提供 `Dockerfile`（node:20 构建 + nginx:1.27 托管）与 `docker-compose.yml`（映射 8080 端口）；当前沙箱无 Docker 守护进程，未实际执行镜像构建，请在本地用 `docker compose up --build` 验证。

页面交互（点击放置站位、签到按钮、表单提交等）可在浏览器中按上表角色逐一操作验证。临时替位场景的手动验证路径：

1. 以**队长**身份打开「走位编排」，选择《丰收锣鼓》——顶部已预置张桂芳（前排1号位）演出前一天请假的推荐面板，秦小梅（身高差1cm、熟练度4、出勤100%、参加最后排练）为首选，冯秀兰未参加最后一次排练标红。
2. 点击某候选人的「确认替位」（选冯秀兰时会二次确认风险），观察：站位变紫（新走位图）、队形变化出现「受替位影响·需重走」、重点排练名单生成、走位记录新增。
3. 切换**服装负责人**：服装页出现「替位服装加急准备」卡；切换**音响师**进「演出当天」：看到更新后的演出清单与「演出前检查」；切换**队员（替位本人）**：走位页蓝框标出其新站位；通知中心各角色均能看到「临时替位」类通知。
4. 若替位人未参加最后一次排练：队长端总览、走位页、演出当天「演出前检查」均持续红色闪烁风险提示。
